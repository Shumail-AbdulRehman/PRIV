## Review notes

- `raiseIssue` can return null for a suppressed ordinary failure; callers that
  consume the return value must handle this. Serious reasons return a case.
- Manager actions accept optional `extensionMinutes`, bounded by the immutable
  task policy and 120-minute ceiling beyond original shiftEnd. Existing session
  capabilities are not prolonged; staff obtains fresh capture authority.
- ACCEPT_CONTEXT is bound to the referenced evidence's session. A waiver or
  ACCEPT_EVIDENCE does not supply that override. Previously accepted evidence
  remains valid through handover; newly accepted revoked evidence requires
  explicit context review.
- PRIVACY_HOLD is independent of requirement fulfillment. Resolve never releases
  original media; a different independently SAFE replacement can satisfy the
  occurrence after explicit manager acceptance.
- No agent-spawning tool was exposed in this delegated session. Work stayed in
  the assigned disjoint scope while the parent and other agents continued.
- Both PostgreSQL suites emitted the existing pg concurrency deprecation warning;
  their assertions and process exit codes passed. Expected constraint-rejection
  logs in the parent suite are negative-test assertions.
- These checks do not establish physical-device reliability, provider accuracy,
  held-out benchmark results, or production Cloudinary delivery behavior.

## Completed-task follow-up resolution

Added nullable VerificationDecision.followUpTaskInstanceId with a restrictive FK,
reverse TaskInstance relation and index, using only the NEW transaction-wrapped
202610060002_verification_followup migration. Earlier migrations were not edited
during this follow-up change. The new migration replaces only the decision binding
trigger; ordinary evidence/issue/actor binding and immutable history remain guarded.

Completed inventory tasks permit only RESOLVE_ISSUE with a durable pointer to a
different completed inventory task in the same company, location and area. The
follow-up must start after the concern; accepted replacement capture and receipt
must also follow issue.firstSeenAt. Affected fixture/view requirements must be
PASSED or MANAGER_ACCEPTED with SAFE received evidence, never WAIVED. Task-wide
concerns require SAFE accepted context from a session contributing non-waived
mandatory evidence to follow-up completion. Matching source media, SHA-256 or
normalized hashes are rejected; pending replacement safety checks block resolution.
These bindings, scope, recency and evidence conditions are checked at the service
and database boundaries.

The immutable decision stores the pointer and selected evidence; event/audit and
case state change atomically with durable request idempotency. Original task,
requirements, assignments and completion fields are untouched, and original HOLD
media remains HOLD. Completed-case detail DTOs advertise RESOLVE_ISSUE only with
requiresFollowUp=true. No inbox UI was changed.

Fresh PostgreSQL tests verify safe manager-accepted fixture replacement, contributing
context replacement, scope/area/foreign-tenant rejection, older and incomplete task
rejection, waived/held/wrong-view replacement rejection, SHA/normalized replay
