## Goal

Taking task photos looks like the design (All screens > Task photos) while the capture logic, which carries the product's trust rules, stays exactly as it is.

## Scope

**Do not change logic.** In `VerificationScreen.tsx`, keep every state variable, effect, ref and function (`load`, `beginPhotos`, `scanned`, `capture`, `sendPhoto`, `checkResult`, `refreshAfterUpload`, `submit`, `action`, the activation effect, the countdown, the account guard `valid()`, temporary file removal, `reconcileSubmission`). Only the returned layout and the copy around it change. If a layout need seems to require a logic change, stop and log it instead.

Per `mode`:
- **prepare / progress / unavailable**: white page with `TopBar` "Task photos" and the restyled `VerificationProgress` (spec 35), passing `onSelect` that runs the same action today's "Take task photos" button runs. If photo authority is missing, the red note "Task photos are unavailable" with the existing explanation stays above the list.
- **scan**: same dark full-screen scanner look as spec 34 (title "Scan the same QR", area line, viewfinder, scan line, torch, restart). Scanning still calls `scanned`.
- **locating**: the busy label from `busyLabel` in a centred card over the dark screen.
- **capture**: dark full-screen camera. Top overlay: close (48, goes back to progress as today's back does), a segment strip with one segment per required photo (white for done states from `photoRow(...).done`, yellow for the current one, dim otherwise), the count "{current}/{total}"; title "{item}: {view}" (`cameraTitle`, translated fixture names); the instruction from `slotInstruction` or `qualityInstruction` as today; the photo window line "{time} left. After that, scan the task QR again." with a timer icon, from the existing `seconds` (`countdown` from spec 05), shown only when `seconds` is not null. A faint dashed outline of the fixture in the middle (`PhotoGuide` restyled to draw the outline and keep its instruction text for screen readers). Bottom bar: "Keep people out of the photo, including in mirrors."; torch (48 round) at the start, the 80 shutter (`PhotoCaptureControls` restyled: white face, ring, scale 0.93 on press, medium haptic) in the middle, labelled with the existing label. While busy, a busy card "Uploading and checking photo…".
- **pending upload** (a captured photo not yet received): the photo preview, "Upload this photo again", the existing failure text, `next` "Upload again" (calls `sendPhoto`), ghost "Take a new photo" if that action exists today.
- **results**: after each upload, if the result needs the person, open a `BottomSheet` instead of inline text, using the existing result data: retake → "Take this photo again" with the specific correction from `photoCorrection`, action "Retake photo"; cleaning required → "This still needs cleaning", "Clean this again. Then scan the task QR to take a new photo.", action "Clean, then scan QR" (closes to the progress list); review or privacy hold → "Waiting for manager review", "Your photo is kept. Continue with the next photo.", "Next photo"; service failure → "Photo check could not finish", "This does not mean it is dirty. Your photo is kept for your manager.", "Next photo"; upload failure → "Photo did not upload", "Check your internet and upload again. If you close this screen, take a new photo.", "Upload again". A clean result shows the message bar "Photo uploaded" and moves on as today.
- **Dock** on the progress list from `nextPhotoAction` (spec 08): `submit` → hint "Your work is ready to submit. Manager review may still be needed." and `next` "Submit work" (calls `submit`); `waitUpload` → `DockStatus` "Waiting for the upload to finish"; `clean` → "Clean, then scan QR"; `retake` → "Retake photo"; `uploadAgain` → "Upload again"; `next` → "Next photo". Offline → `DockStatus` "Internet needed to continue".
- **finished**: `SubmissionReceipt` (spec 36) with the task id, area, `staffSubmittedAt`, received and required counts, `hasNextTask` from today's feed cache, `onNext` navigating to My day (which shows the next task) and `onDone` going back.
- "Refresh results" stays reachable as a ghost button under the list; "Back to tasks" is the top bar back.
