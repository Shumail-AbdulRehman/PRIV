The existing attendance list and staff attendance history expose a record-specific context dialog. Original attendance day, expected shift, captured arrival/departure/status and protected-photo availability are separate from appended context. Shift/capture/annotation timestamps use the saved location timezone; the persisted attendance day is a UTC calendar label. No geofence success, corrected paid hours, fabricated worker name or identity claim is inferred. The existing08 protected-media component remains the only photo access path; no raw historical image URL is read.

`contextApi.ts` consumes23 GET/POST `/api/attendance/:id/annotations`. Read pages contain25 chronological records and only follow the server UUID cursor. Attribution uses actual server role/account ID/time; user-entered reason is escaped text, not markup. Acknowledgements reference an exact note. ADMIN/MANAGER may acknowledge; STAFF reusable rendering offers only notes, while operational web routing continues27's Android audience boundary. Backend authorization always decides tenant/site/self/current access; UI never supplies actor or timestamps or edits/deletes saved notes.

A trimmed1–1000 character reason is mandatory. Submission sends only kind/reason/random UUID requestId and optional exact parentId. The UUID is retained with its immutable intent until acknowledged. An uncertain/lost response locks the draft for an exact retry; concurrent clicks cannot start another request.409 keeps the draft and requires explicit conflict review/refetch before releasing it for another intent. Only server acknowledgement clears the draft and refetches authoritative history. Closing/reopening keeps the same draft; a company/role/account/attendance change remounts it, preventing another principal from inheriting context state. Loading, empty, transient error, denial, conflict, uncertain save and success are distinct. Raw server/driver messages never render.

This is an approved design/v5 extension with incumbent dialog, buttons, status badge and semantic tokens. Separate flat facts/history/form sections, readable EN/UR and bounded scrolling preserve existing operational UI. A sticky labelled close control remains reachable while reading long context. No package, backend behavior, schema, migration, production data/configuration or design-system replacement is introduced.
