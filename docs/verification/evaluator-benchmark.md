# Coverage and cleanliness evaluation evidence

Steps 12–13 implement independent quality, privacy, coverage/identity, duplicate and reference-free per-surface cleanliness stages. Production auto-pass remains unconditionally disabled in `autoPassAllowed`. No consented development/held-out image dataset was supplied or evaluated. No live vendor accuracy, latency, prices or device reliability are claimed. The checked-in JSON reports `DATASET_UNAVAILABLE`, null confidence intervals/cost/latency and unsuccessful release gates.

Run from `backend`:

```sh
./node_modules/.bin/tsx scripts/verificationEvaluatorBenchmark.ts
./node_modules/.bin/tsx scripts/verificationEvaluatorBenchmark.ts /path/to/results.json /path/to/new-report.json
./node_modules/.bin/vitest run src/services/verification-v2/evaluators.test.ts src/services/verification-v2/provider.contract.test.ts src/services/verification-v2/evaluatorBenchmark.test.ts src/services/verification-v2/quality.service.test.ts
```

The offline harness consumes a JSON array of independently labelled, consented examples and evaluator predictions. The strict row contract is in `evaluatorBenchmark.ts`: IDs, room/fixture/type, development/heldout split, visibility, identity, cleanliness, predicted cleanliness, wouldAutoPass, provider/model/prompt/rubric versions, latency and nullable measured cost. It rejects duplicate IDs, room/fixture leakage and mixed evaluated configurations. Obtain consented photos across phones, lighting, wear, stains, reflections, wrong items and replay transformations; reviewers must label visibility, identity and visible cleanliness separately. Run the separate evaluators on those images and export their predictions without granting production credit. Never treat generated unit fixtures as real held-out evidence.

The report counts false-clean outcomes on DIRTY examples and auto-passes on known wrong/replayed examples separately, with 95% Wilson intervals and fixture-specific counts. Targets require at least 100 held-out DIRTY and 100 wrong/replayed examples, no wrong/replay auto-passes, and false-clean rate at most 2%. Aggregate target success does not establish eligibility for sparse fixture types, does not eliminate sampling uncertainty and never changes runtime eligibility. Cost remains null when any measured cost is missing; adapters record normalized token usage and unknown monetary cost as null rather than inventing pricing.

Duplicate matching searches all same-company exact byte/normalized hashes, all task evidence and the newest 200 relevant same-company fixture/type assets over 30 days. Mirror and explicit 80% center-crop variants are persisted in quality results and compared with Hamming distance ≤8. Candidate links remain review evidence, never a fraud finding. Up to three screened candidate images are paired with the current image and safe session context for coverage assessment. Search bounds limit computation, not retention. Old assets without persisted variants retain their original perceptual-hash comparison; no evidence deletion/backfill is performed.

Privacy and coverage validate injected as well as configured provider results. Cleanliness requires a version-1 snapshot with nonempty criteria and a declared supported view, and immutable `surfacesByView`, then assesses every snapshotted surface. Older snapshots lacking this mapping require review. Missing/extra/repeated surfaces, inconsistent aggregate verdicts, hidden surfaces aggregated CLEAN and missing rubric criteria cannot pass. Unknown/custom view mappings require rubric review. OpenAI requests strict JSON Schema; Gemini receives JSON Schema and both responses are validated locally. Refusals, malformed JSON, truncation and outages produce no fabricated verdict or vendor fallback. Durable job results retain evaluator version and provider metadata; privacy success permits a screened manager derivative even when capture authority is review-only.

Parent integration interface: retain `processVerificationJob(job, provider, read)`. Fake cleanliness responses must use the surfaces exported by `viewSurfaces` (for example `bowl` and `seat`, not `bowl_seat`). Ingestion owns the same-tenant exact SHA advisory lock. Completion/evidence owners must also enforce active company status. Database concurrency, live vendor contracts, consented held-out evaluation and physical-device gates remain separate required release evidence.

Successful jobs for the same stage/evaluator version are reused without another provider call. A different-version recheck retains its assessment only in immutable versioned job history; canonical attempt results and decisions remain unchanged. Quality threshold version is separate from DCT hash algorithm version. A crash between external response and durable publication can still cause a repeated bill; exactly-once billing is not claimed.

Provider metadata `model` records OpenAI response.model or Gemini response.modelVersion when returned, falling back to the requested identifier only when absent. `requestedModel` independently retains the configured alias. `providerVersion: adapter-v1` identifies adapter code, not the vendor model revision. Benchmark rows should export this returned model identity and may include requestedModel; mixed returned/requested configurations are rejected within a report. Monetary cost stays null when unknown. Coverage expects immutable nameSnapshot/itemCodeSnapshot and returns observedLabel; PRINTED_LABEL MATCH requires that observed label to equal one of those two immutable identifiers.

Final steps 12–13 audit: all retained decodable captures now reach privacy screening even when quality fails. A SAFE poor-quality capture stays recapture-required, without being incorrectly marked privacy HOLD; coverage/cleanliness require canonical quality acceptance. Coverage receives only the latest context-slot attempts. Serious context/privacy/stale-authority/exact-reuse issues escalate immediately; ordinary context recaptures use the snapshotted policy threshold. Privacy flags take precedence over identity validation and also restrict derivatives on versioned rechecks. Provider bytes require authenticated stored media identifiers. Empty existing-number configuration cannot establish identity. Parent generation, latest-context aggregation and lease guards are preserved.

Optional standards now use `standardPrivacy.service.ts` after retained storage and standard registration. A validated SAFE assessment permits protected review delivery; HOLD/UNCERTAIN restrict the original and derivative, and failures remain PENDING. The existing standards POST accepts `{standardId}` for an authorized retry. Audit records serialize calls with a short lease, bound them to four attempts, persist metadata and reuse success; ordinary retries never release a HOLD. These optional checks run on request rather than in the task-attempt queue, and do not fabricate task evidence or task completion credit.
