# Spec 50 — Pure billing display states and exact recurring prices

`frontend/src/pages/Subscription/onboarding/billingViewState.ts` exports deriveBillingViewState(input). Supply current owner `{companyId, ownerId}`, dataOwner attached to the query result, raw unwrapped lifecycle data, read status (`loading | fresh | stale | error`), optional HTTP status, local uncertain flag and activation-return flag. parseBillingLifecycle validates the boundary again; no clock, request, storage or React dependency. Do not stamp old responses with the current owner identity. Query identity/cancellation remains51.

The state carries kind/reason, matching validated data or null, and explicit canChoosePlan/canOpenWorkspace/canOpenPortal/resume. Consume these display action fields rather than inferring actions from raw data. Matching stale/error records may be displayed but authorize no actions. Foreign/denied/invalid identities never expose records. No count or limit is clamped. Fresh restricted/reconciliation states precede permission; explicit workspaceAccessAllowed alone can yield confirmed, never status/date/URL inference. Browser return alone yields pending; linked canceled/expired/past-due records use existing account billing; unknown subscription is pending; exact server-proven READY resume takes precedence over selection. Existing server portal capability is separately exposed for fresh authorized data, including recovery/restriction where permitted.

State decision order: invalid actor/denied → unavailable; loading → checking; missing/mismatched dataOwner/data company/invalid DTO → unavailable; stale/error → unavailable with matching stale data; administrative restriction → restricted; server reconciliation → uncertain; explicit server permission → confirmed; local uncertainty → uncertain; unknown subscription → pending; linked subscription/mirror → existing; ready configured checkout → resume or choose-plan (activation URL without resume remains pending); awaiting/return → pending; otherwise unavailable. No backend entitlement policy is copied into this helper.

billingPlanDefinition(plans, code) consumes API-supplied availablePlans and returns the unique matching definition with ADVANCED displayed as Enterprise; no match or duplicate is null. All capacities/features/descriptions remain API facts, not a second copy of backend limits. Existing helpers/types are extended through explicit feature imports, no barrel introduced.

`frontend/src/pages/Subscription/onboarding/billingPrice.ts` exports formatBillingPrice(amount, currencyCode, interval, locale='en-PK'). It returns null for malformed/unsupported inputs, otherwise `{formatted, decimalAmount, currencyCode, fractionDigits, interval}` describing the full recurring provider price. Amount must be canonical nonnegative integer text up to32 digits; numeric unsafe inputs, negative/fractional/scientific strings, invented currency codes and invalid locales fail closed. A zero price remains a real formatted zero.

Minor-unit digits come from the runtime Intl currency rules after requiring Intl.supportedValuesOf('currency') membership. BigInt formats the integer part exactly; localized individual fraction digits replace formatter fraction parts without converting money to Number. This preserves values beyond MAX_SAFE_INTEGER. Yearly prices retain the full annual amount/interval; no monthly equivalent, discount, trial or amount-due-today is computed. Recurring wording and bdi direction belong to screen consumers. Currency support reflects the deployed browser Intl/ICU implementation; unavailable support returns null rather than guessing.
