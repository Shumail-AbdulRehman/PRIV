# Spec 51 — Validated owner reads and recoverable billing polling

`frontend/src/pages/Subscription/api.ts` retains all existing names. getBillingLifecycle(signal?, companyId?) validates with parseBillingLifecycle and rejects a mismatched expected company. getBillingCatalog and prepareBillingCheckout validate through spec45 parsers. Every private read consumes AbortSignal and checks cancellation again after transport completion, so a transport that resolves late cannot deliver usable data. getSubscription(signal?, companyId?) retains API-supplied availablePlans and checks the expected company for scoped consumers; no capacity/price list is copied locally.

prepareBillingPortal validates its transient returned URL before exposing it; navigateToBillingPortal validates again. Only HTTPS exact approved Paddle portal hosts are accepted; userinfo, explicit ports (including443), whitespace/backslashes, alternate protocols and lookalike hosts reject generically. Portal URLs are never placed in query keys/cache/history by this layer. Existing controller identity/server checks remain mandatory in53; a safe URL alone is not purchase/actor authorization. Direct POST functions perform no automatic retry.

`frontend/src/pages/Subscription/queries.ts` exports billingLifecycleKey/companyId/ownerId and billingCatalogKey/companyId/ownerId key factories. useSubscription now includes both company and owner IDs in its private key, retains API availablePlans and existing owner/manager semantics. usePricingContext remains public. Private billing scope cleanup cancels/removes obsolete subscription/lifecycle/catalog keys on identity/role transition and first mount. Private hooks use gcTime0 for unobserved records; TanStack signal consumption cancels pending requests when the last observer disappears. Cache is short-lived memory only; no auth/billing persistence mechanism is introduced.

useBillingLifecycle({poll?}) retains the query result plus current dataOwner `{companyId, ownerId}`, pollingTimedOut and refreshBilling. Its exposed refetch resets the polling budget for explicit manual recovery; refreshBilling also invalidates only the still-current cached owner's catalog after a successful read. Matching stale data stays available for display after a read failure, while isError remains true; display/action consumers must use identity/freshness rules from50. Former owner records cannot authorize a new principal. Read cancellation and expected-company checking complement server authorization rather than replace it.

Pending/unknown/reconciliation lifecycle polling backs off2/5/10/30 seconds (30 thereafter), stopping after a two-minute active budget with pollingTimedOut. Each effect timer is cleaned on data/status/scope changes and unmount. Unknown initial transient failures can recover within the same budget. Known settled/confirmed states stop polling;401/403 stop polling/focus/reconnect refetch until explicit recovery. Manual refresh remains available after timeout. Focus/reconnect can refresh current permitted reads; no checkout POST is triggered. No server hold is cleared by a local timer.

useBillingCatalog() is an owner-only validated catalog READ with cancellation, reconnect/focus refresh and no automatic mutation. It is deliberately independent of checkoutAvailable/reconciliation/local uncertainty, allowing truthful plan data without enabling a purchase. Consumers still render explicit loading/error/unavailable states and use lifecycle/controller capability fields for actions. This seam replaces component-owned catalog queries in later screens; legacy SubscriptionPage composition remains owned by59.

useCustomerPortalSession retains its old callable name and now explicitly disables mutation retry and uses gcTime0. The new managed portal action uses the direct transient API boundary, not a persistent query. No new HTTP client/state library is introduced.
