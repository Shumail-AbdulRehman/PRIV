# Spec 53 — Scoped single-checkout controller

`frontend/src/pages/Subscription/onboarding/useBillingCheckout.ts` exports useBillingCheckout(). Mount once for the owner payment/action boundary. It reuses Redux identity, actual getCurrentUser, validated billing API and the project Paddle singleton/event subscription. No extra endpoint/client, React Query mutation history, browser storage, URL transaction parameter or persistent checkout state is introduced.

Public result: status (`idle | loading | open | reopenable | pre-submit-error | uncertain | pending`), safe translatable message/null, prepared exact `{plan, interval, transactionId}`/null, isBusy, openCheckout(selection?) and checkStatus(). New selection is `{plan: PlanCode, interval: month | year}`. Without selection, openCheckout requires a server-proven prepared resume. checkStatus only reads/reconciles; it never initializes Paddle or posts checkout. Safe messages use vocabulary published in47. Consumers derive confirmed workspace UI from fresh lifecycle permission via50/51, never controller status or SDK success.

An identity-generation object also prevents same-owner signout/sign-in from reviving prior mounted-session state. A layout effect retires callbacks as identity changes commit and owns a mounted company/owner/role session, synchronous submission lock, current AbortController and subscription cleanup. Initial and post-SDK owner/lifecycle checks prevent stale actor/restriction/linked/foreign/configuration from mutating. Exact browser/server sandbox-production and token-family agreement is required. SDK initializes before the new POST; live owner verification + existing approved policies/configured contact remain headless prerequisites, while sandbox avoids fetching those live commercial prerequisites. No production configuration or business terms change.

A valid prepared POST result stays in owner-local memory, including after SDK open failure. Reopen requires fresh exact server checkoutResume match and retains the ID; changing the plan/interval cannot prepare or open a replacement. Reload can restore the exact server selection through openCheckout()/checkStatus. Lost/malformed POST responses and409 latch local uncertainty; another read merely advertising READY with no proven resume cannot trigger a second POST. Only server-proven matching draft permits reopen; a completed/linked/paid/restricted/reconciliation state never buys again. No timeout clears the server hold.

One subscribed callback compares event transaction_id to this active owner's prepared transaction. Wrong/missing/old-owner events are ignored. Closed yields reopenable (unless pending/uncertain); completed yields pending and blocks reopening/new purchase; checkout/payment errors/failure yield status-first uncertainty. These events invalidate only that owner's lifecycle plus currentUser, never write a ready/paid flag or infer workspace permission. A synchronous close during open is not overwritten with open state. Provider event payload details are not exposed as error text.

Unmount/account change aborts work, unsubscribes, ignores late responses/events and closes only an overlay opened by this controller. Its unobserved lifecycle cache writes are removed on cleanup; observed lifecycle remains managed by51. API read results stored in the private current key are validated server facts, not browser grants. Prepared IDs/errors remain transient; no private values are logged.
