1. WHAT THIS PROJECT DOES
--------------------------------------------------------------------------------
CleanOps is a cleaning / facility-operations management SaaS. Core workflows:

- Managers use a React web dashboard to create companies, locations, staff
  (cleaners), managers, and recurring/one-off task templates.
- The backend automatically generates daily task instances from templates.
- Staff use a React Native mobile app to log in, check in/out (with geofencing),
  view today's tasks, scan a QR code to start a task, and upload proof images
  to complete a task.
- Cron jobs run on the backend to generate tasks, update attendance status,
  mark missed tasks, and auto-reassign tasks that were not started within a
  grace period.

3. ARCHITECTURE
--------------------------------------------------------------------------------
- Monorepo with backend, frontend, and frontend-mobile apps.
- Backend exposes /api/* on port 8080 by default.
- Auth: JWT access token in cookie (accessToken) or Authorization: Bearer header;
  refresh via POST /api/common/refresh-token.
- Database: Prisma Client + pg adapter reads DATABASE_URL.
- File storage: Proof images uploaded to Cloudinary.
- Frontend dev uses Vite proxy to 127.0.0.1:8080.
- Mobile app uses EXPO_PUBLIC_API_BASE_URL (default Android emulator 10.0.2.2:8080).
- Cron jobs imported at startup in backend/src/app.ts.

B. EXISTING DATA MAY BE 5 HOURS OFF AFTER UTC SWITCH
   Under the old Karachi logic, shift times were stored as UTC instants that
   represented Karachi wall-clock time (e.g., 9 AM Karachi stored as 04:00:00Z).
   With UTC everywhere, that same stored value is now interpreted as 4 AM UTC.
   Existing staff shifts, task template shifts, effective dates, and attendance
   windows need a data migration if the historical values should remain correct.
   A SQL migration to shift old timestamps by +5 hours could be written once the
   database is reachable.

C. BILLING MIGRATION NOT APPLIED
   backend/prisma/migrations/20260811192000_remove_billing_tables/migration.sql
