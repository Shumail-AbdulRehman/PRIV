1. WHAT THIS PROJECT DOES
--------------------------------------------------------------------------------
CleanOps is a cleaning / facility-operations management SaaS. Core workflows:

- Each company has ONE admin (the signup-created account). The admin creates
  locations and managers via the React web dashboard.
- Each manager is assigned to at least one location and can manage several.
  A location can belong to ONLY ONE manager (exclusive assignment).
- Managers are strictly scoped: they only see/manage staff, task templates,
  tasks, attendance, and dashboards for their assigned locations.
- The backend automatically generates daily task instances from templates.
- Staff use a React Native mobile app to log in, check in/out (with geofencing),
  view today's tasks, scan a QR code to start a task, and upload proof images.
- Cron jobs run on the backend to generate tasks, update attendance status,
  mark missed tasks, and auto-reassign tasks not started within a grace period.
- All scheduling is per-location timezone aware: every location has an IANA
  timezone, auto-detected from its coordinates (overridable).

3. ARCHITECTURE
--------------------------------------------------------------------------------
- Monorepo with backend, frontend, and frontend-mobile apps.
- Backend exposes /api/* on port 8080 by default.
- Auth: JWT access token in cookie (accessToken) or Authorization: Bearer header;
  refresh via POST /api/common/refresh-token.
- Roles: ADMIN (company owner, one per company, created at signup), MANAGER
  (created by admin, location-scoped), STAFF (mobile app users).
  - Role enum in Prisma: ADMIN | MANAGER | STAFF (all on the Manager/Staff tables).
  - verifyJwt loads ADMIN/MANAGER from prisma.manager, attaches
    req.user.locationIds for MANAGER (from ManagerLocation), rejects inactive
    accounts.
  - authorize(...roles) middleware factory guards routes.
  - backend/src/utils/scope.ts: getScopedLocationIds (null = ADMIN unrestricted),
    assertLocationAccess (403 for out-of-scope MANAGER).
- Database: Prisma Client + pg adapter reads DATABASE_URL.
  - Migrations MUST run through the session-mode pooler (port 5432), not the
    transaction pooler (6543): override DATABASE_URL port before
    `npx prisma migrate deploy`. The app runtime keeps using 6543.
- TIMEZONE MODEL (important):
  - Location.timezone = IANA name (e.g. "Asia/Karachi"). Default for existing
    rows: "Asia/Karachi".
  - Every DateTime in the DB is a real UTC instant. Wall-clock meaning comes
    from the owning location's timezone (09:00 at a Karachi location = 04:00Z).
  - Day anchors (TaskInstance.date, Attendance.date) = start of the location's
    LOCAL day as a UTC instant (Karachi: 19:00Z previous UTC day).
  - backend/src/utils/dateTime.ts holds both legacy UTC helpers and the zoned
    helpers (getZonedDayRange, getZonedDayRangeFromDateInput, getZonedMonthRange,
    getZonedClockMinutes, withZonedClockOnLocalDay, resolveZonedAttendanceWindow,
    isValidTimeZone). Location-scoped logic must use the zoned helpers.
  - Timezone auto-detection: createLocation/editLocation derive timezone from
    latitude/longitude via tz-lookup when not explicitly provided (fallback
    "UTC"). Frontend picker defaults to "Auto-detect from coordinates".
  - Frontend formats times per-record location tz via formatInTimeZone; time
    inputs convert via fromZonedTime. Calendar-date-only values stay UTC.
  - Mobile app: no changes (staff are physically at their location; device-local
    display is correct).
- File storage: Proof images uploaded to Cloudinary.
- Frontend dev uses Vite proxy to 127.0.0.1:8080.
- Mobile app uses EXPO_PUBLIC_API_BASE_URL (default Android emulator 10.0.2.2:8080).
- Cron jobs imported at startup in backend/src/app.ts.
